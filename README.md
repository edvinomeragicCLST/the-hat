# The Hat

A small academic 2D platformer made with Godot. It was created for a presentation to the university dean to encourage interest in a game-development class. The protagonist is inspired by the dean, and the premise is to retrieve his signature hat.

## Gameplay

- Start from a menu with **Play** and **Quit** buttons.
- Run and jump across tile-based platforms in two level scenes, with a camera following the player.
- Collect cherries: each collected cherry adds one point to the current level's on-screen counter. Level 1 contains 18 cherries; Level 2 contains 13.
- Touch the hat to enter Level 2. The current script always loads Level 2, including when touching the hat in Level 2, which restarts that level. There is no final victory screen.
- Points start at zero whenever a level loads; collecting every cherry is not required to reach the hat.

These details come from the scripts and scenes, rather than from the animations or unused assets bundled with the project.

## Controls

| Action | Control |
| --- | --- |
| Move left | A |
| Move right | D |
| Jump while on the floor | W |
| Start / exit from the menu | Click Play / Quit |

Movement uses physical key positions from `project.godot` (A/D/W on a QWERTY keyboard). There are no custom arrow-key, spacebar, controller, or touch movement bindings. Close the game window to exit during play; when running from the editor, F8 stops the project.

## Requirements

Use the **standard Godot 4.2.x editor**; .NET is not required. The project declares the `4.2` feature version and uses Godot 4 scene format and APIs. The original patch version is not recorded. Godot 3 is incompatible.

The project uses the **Mobile renderer**, so normal graphical play needs Vulkan support. Headless checks do not establish graphics compatibility. Newer Godot 4 versions may upgrade project metadata; use a separate copy when testing an upgrade. See [PUBLICATION_REVIEW.md](PUBLICATION_REVIEW.md) for the exact editor version used for local validation and its limits.

## Open and run

1. Download or clone the project into a writable folder. Keep the source assets and their adjacent `.import` files together.
2. In Godot 4.2.x, choose **Import**, select `project.godot`, and open it. Allow the initial asset import to finish; the `.godot/` cache is generated locally.
3. Press **F6** only to test a selected scene, or **F5** / **Run Project** to start at `scenes/Main menu.tscn`.
4. Click **Play**, then use A/D/W to move and jump.

With a Godot executable on your PATH, the equivalent commands from this folder are:

```sh
godot --editor --path .
godot --path .
```

For a clean import/parsing check without opening a window:

```sh
godot --headless --path . --editor --import
godot --headless --path . --quit-after 120
```

Executable names differ by installation. The second command is a startup smoke check, not a full playthrough. No export presets or packaged builds are supplied. Export future builds into an ignored `exports/` directory, and keep signing credentials in ignored local files.

## Project structure

| Path | Purpose |
| --- | --- |
| `project.godot` | Project settings, main scene, input actions, gravity, renderer |
| `scenes/Main menu.tscn` | Menu and text title |
| `scenes/Level1.tscn`, `scenes/Level2.tscn` | Platform layouts, collectibles, hat, camera and score UI |
| `scenes/Main character.tscn`, `scenes/Main character.gd` | Player scene, running, jumping and animation |
| `scenes/cherries.*` | Cherry pickup scene and scoring callback |
| `scenes/trophy.*` | Hat scene and level transition callback |
| `GameManager.gd` | Per-level points counter |
| `Button.gd`, `Button2.gd` | Menu scripts |
| `lemes/` | Protagonist animation frames and hat artwork |
| `Free/` | Bundled pixel-art asset pack, including many unused sprites |
| `icon.svg` | Godot project icon |

Source-side `.import` files preserve import options and resource UIDs. Keep them in version control. Keep any `.uid` sidecars generated by a future Godot upgrade too; this Godot 4.2 source has none. The `.godot/` cache and editor-local state are ignored.

## Known limitations

- This is an academic prototype. No death/respawn, pause, save system, combat, enemy behavior, or in-game restart control is implemented. Falling outside the level can leave the player falling indefinitely.
- The hat script ignores the scene's exported `target_level` setting and always loads Level 2. Level 2's configured menu destination is therefore not used.
- Crouch, climb, hurt, enemies and traps exist as asset files but are not implemented gameplay features.
- A missing menu-title image was replaced with a plain text title for reproducible startup. Its orphan `.import` file is retained, as is an orphan import sidecar for a missing, unused Ninja Frog run sheet.
- The unrelated `scenes/MothCompleted1.25.obj` model is retained locally but excluded from publication, along with its import sidecar. It is not referenced by the game, has unclear provenance, and exceeds GitHub's regular-file size limit. A local Godot editor may still import it because `.gitignore` controls Git, not Godot.
- Graphics, complete level traversal and Godot 4.2 runtime compatibility require manual verification; see the publication review for checks actually performed.
